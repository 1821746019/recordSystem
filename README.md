# 🖨️ 学生打印记录系统

给校园打印店 / 文印室用的轻量记账工具：**一次勾选多个学生，填一个张数，自动算钱、结账、出报表**。

纯前端、零依赖、离线可用；核心业务逻辑与界面完全分离，**后续可直接迁移到微信小程序**。

---

## 一、计价规则（已简化到极致）

**只有一条规则：每张多少钱。** 默认 **0.30 元/张**，不区分单面双面。

```
本次金额 = 打印张数 × 单价
```

| 场景 | 计算 | 金额 |
| --- | --- | --- |
| 打印 5 张 | 5 × 0.30 | **1.50 元** |
| 打印 20 张 | 20 × 0.30 | **6.00 元** |
| **半张（0.5 张）** | 0.5 × 0.30 | **0.15 元** |
| 5 个学生，每人 5 张 | 每人 1.50 × 5 人 | **7.50 元**（合计） |

说明：

- 界面和数据里**都只记一个「张数」**，不再区分单面/双面，也不再统计页数（因为已经无从得知）。
- **张数支持半张**：粒度是 0.5（1、1.5、2…），快捷按钮里有 `0.5`，`+ / −` 也是 0.5 一步。
  金额仍按「分」取整，所以就算单价是 0.25，0.5 张也会算成 13 分而不是 12.5 分。
- 单价随时可在「设置」页改，且**只影响之后的新记录**——历史记录会保留当时的价格。
- 金额内部一律用「分」为单位的整数运算，不存在 `0.1 + 0.2 = 0.30000000000000004` 这类浮点误差。

## 二、核心功能

### ✍️ 记账（批量，最常用的一屏）

针对「一个班好几个人的卷子一起印」这种场景设计：

1. **一次勾选多个学生** —— 支持**拼音 / 首字母搜索**：输 `zxm` 命中张小明、`zhangxiao` 也认、`xm` 能找"小明"，
   还能搜班级（`高一` 或 `gy`）和学号；带关键字时**按相关度排序**（越像的越靠前）。
2. **★ 逗号分隔，一次输多个名字并自动勾选** —— 在搜索框里输入 `zzh,zqy`，
   就会自动把匹配到的学生（郑卓涵、郑卓欢、郑琪烨）全部勾上；继续追加 `,zjb` 会把郑佳堡也勾上。
   - 支持 `,` `，` `;` `；` `、` `/` `|` 等分隔符（空格不算，空格仍是「同一个人」的多条件）
   - 每个词**至少 2 个字符**才自动勾选，避免只输一个字母就选中一大片
   - **手动取消的人不会被自动勾选覆盖**：取消郑卓涵后再追加 zjb，郑卓涵仍然保持未勾选
   - 删掉某个词（如把 `,zjb` 删掉），它自动勾上的人也会自动退掉
   - 清空搜索框 = 这一轮结束，排除记录一起重置
   也可以直接点候选列表手动增减；下拉列表**顶部固定着操作条**「全选这 N 人 / 清空已选（N）」
3. **填一个张数**（每人）—— 步进器 `− / +` 按 **0.5 张**一步，快捷值 `0.5 / 1 / 2 / 5 / 10 / 20 / 清零`，
   也能直接键盘输入小数。这批学生共用同一份张数。
4. **实时看钱** —— 大字显示「每人 ¥1.50 × 5 人 = **¥7.50**」。
5. **保存** —— 每个学生各生成一条**独立记录**（方便分开结账），但共享一个批次号：
   - 「保存记录」：保存后保留已选学生，清空张数（适合同一批人继续记下一单）
   - 「保存并清空」：全部清空（迎接下一批人）
   - 保存后出现「**撤销这一批**」，误操作一秒回退

选中学生时会显示「已选 3 人 · 未结清合计 ¥4.50 · 历史累计 ¥30.60」，收款前心里有数。

### 📋 记录

- 搜索学生/备注、日期区间（今天/本周/本月/全部）、未结清/已结清筛选
- 批量记账产生的记录带「**同批 N 人**」标记
- 单条：结算 / 编辑 / 删除 / 撤销结清；批量：全选后一起结算或删除
- 实时汇总当前筛选结果：条数、金额、未结清、张数
- 一键导出当前筛选结果为 CSV

### 🧑‍🎓 学生

- 档案管理（姓名、班级、学号、电话、备注）
- **名单导入 / 导出（CSV）**：能从 Excel 直接粘贴，或把花名册另存为 CSV 批量建档
  - 导出五列：`姓名,班级,学号,电话,备注`，**导出的文件可以原样再导入**
  - 导入前先预览：将新增几人、库里已有几人、哪几行读不懂（报的是 Excel 行号）
  - 重复按「姓名 + 班级」判定；可选「跳过」或「用名单更新电话 / 学号 / 备注」（空单元格不会清空已有值）
  - 表头可识别（顺序随意、缺列也行）；没有表头就按上面五列的顺序读
- 卡片直接显示：未结清金额、累计消费、累计张数、最近打印时间
- 「结清全部」一键生成收款单；展开看最近 20 条明细
- 排序：未结清 / 消费额 / 姓名 / 最近打印
- 删除学生时可选「是否连同打印记录一起删」（默认保留历史）

### 📊 统计

- 总览 8 项：学生数、记录条数、打印张数、人均张数、应收、实收、未结清、已结清
- 欠款名单（一眼看到谁还没给钱）、月度汇总表、学生消费排行
- **批量记账批次**：每一批给多少人、每人多少张、本批合计多少钱，可整批撤销
- 收款记录列表，可整笔撤销（关联记录自动回到未结清）
- 导出 4 种 CSV：记录明细 / 学生汇总 / 收款记录 / 批次汇总（带 BOM，Excel 不乱码）

### ⚙️ 设置

- 修改单价（元/张）、系统名称、操作人
- **备份为 JSON** / **从 JSON 恢复**（可选「覆盖」或「合并」，导入前预览数据量）
- 载入示例数据、清空业务数据、恢复出厂设置

## 三、怎么用

**方式一：直接打开** — 双击 `index.html` 即可（不需要服务器、不需要联网）。

**方式二：本地起服务**（推荐手机/平板访问）

```bash
cd recordSystem
python3 -m http.server 8080   # 浏览器打开 http://localhost:8080
```

手机上强烈建议**装成桌面 App**（PWA）：装完以后可以**完全断网使用**，全屏、无地址栏。
安装方法见下文「[十、离线使用](#十离线使用装到手机桌面)」。

> 想先跑起来看看？`file://` 双击也能用，但浏览器会把它当成「不安全来源」，
> 部分浏览器会直接禁用 `localStorage`（账本就存不住）——只建议用来快速预览。

**第一次打开**：去「设置 → 载入示例数据」看效果，确认后「清空业务数据」开始正式用。

**为什么这样分层？**

`js/core/` 里没有 `document`、没有 `window`、没有 `localStorage`（存储通过适配器注入），
所有函数都是「输入数据 → 输出数据」。这意味着：

- 换界面（网页 → 小程序 → 未来的 App）时，**业务逻辑一行都不用改**；
- 存储方式想换成微信缓存、云数据库、自建后端，**只需要写一个新的适配器**；
- 可以在 Node 里直接跑单元测试（项目里的 267 项测试就是这么跑的）。

`store.subscribe(fn)` 是数据驱动界面的关键：任何数据变化 → 自动重新渲染当前页面，
小程序里换成 `setData` 也是同一套思路。

## 五、数据结构（v3）

整棵状态树作为一个 JSON 存在一个 key 里（`pps_data_v1`），简单、可整体备份：

```jsonc
{
  "version": 3,
  "settings": {
    "shopName": "打印记录系统",
    "operator": "",
    "priceFen": 30            // 单价 0.30 元/张（单位：分）
  },
  "students": [
    { "id": "stu_x", "name": "张小明", "className": "高一(3)班",
      "studentNo": "20240301", "phone": "", "note": "",
      "createdAt": 1740000000000, "updatedAt": 1740000000000 }
  ],
  "records": [
    { "id": "rec_x",
      "batchId": "bat_x",      // 批量记账的批次号；单条记录为空字符串
      "studentId": "stu_x", "studentName": "张小明", "className": "高一(3)班",
      "date": "2025-04-01", "time": "14:30",
      "sheets": 5,             // ← 只有张数，没有单/双面；可以是 0.5 的倍数
      "priceFen": 30,          // ← 下单时冻结的单价
      "amountFen": 150,        // 5 张 × 30 分
      "note": "数学周测卷 全班统一",
      "paymentId": null, "paidAt": null,
      "createdAt": 1740000000000, "updatedAt": 1740000000000 }
  ],
  "payments": [
    { "id": "pay_x", "studentId": "stu_x", "studentName": "张小明",
      "date": "2025-04-02", "method": "微信",
      "shouldAmountFen": 450, "amountFen": 440, "discountFen": 10,
      "note": "抹零", "recordIds": ["rec_x", "rec_y"], "createdAt": 1740000000000 }
  ]
}
```

**四个关键设计**

1. **只记张数**：v3 起记录里只有 `sheets`，金额 = 张数 × 冻结单价，改价永远不会污染历史账单。
2. **金额用「分」**：整数运算，没有浮点误差。
3. **批量 = 同一个 `batchId`**：一次提交的 N 条记录共享批次号，可整批撤销；
   但每条记录仍属于各自的学生，**结算、欠款、账单都是分开的**——不会因为"一起录入"就搅在一起。
4. **结清 = 记录挂上收款单**：`未结清金额 = Σ 未挂 paymentId 的记录金额`，
   逻辑单一，不会出现「收款总额对不上」的经典糊涂账。撤销就是把 `paymentId` 摘掉。

### 旧数据自动升级

| 版本变化 | 自动处理方式 |
| --- | --- |
| v1 → v2 | 单/双面两个单价合并为统一单价（取原来的**双面价**） |
| v2 → v3 | `singleSheets + doubleSheets` 合并为 `sheets`，去掉页数概念 |

- 历史的 `amountFen` **一律原样保留**，不会被重算（旧账不会因为改规则而变化）。
- 打开时控制台会提示 `数据已从 v1 升级到 v3`，之后保存即为新结构。

## 六、拼音搜索（顺便说明为什么"内联"一个第三方库）

搜索支持这些写法，全部命中同一个人：

| 你输入 | 匹配到 | 依据 |
| --- | --- | --- |
| `张` / `小明` | 张小明 | 原文（前缀 / 包含） |
| `zxm` | 张小明 | 拼音首字母 |
| `zhangxiaoming` / `zhangxiao` | 张小明 | 全拼 |
| `zhangxm` / `zxiaoming` | 张小明 | 拼音 + 首字母混打 |
| `xm` / `xming` | 张小明 | 从名字中间开始 |
| `高一` / `gy` / `gaoyi` | 高一(3)班 的所有学生 | 班级也参与匹配 |
| `20240301` | 对应学号的学生 | 学号 / 电话 |
| `zxm 高一` | 交集 | 空格分隔＝多个条件同时满足 |

命中的结果会**按相关度排序**：原文完全相同 > 全拼相同 > 原文前缀 > 全拼前缀 > 首字母/混打 > 中间片段。

### 用的是哪个库、为什么这么引

用 [tiny-pinyin](https://github.com/creeperyang/pinyin)（MIT，v1.3.2），但**不用 npm 依赖**，
而是把它打包成**单文件**放进 `js/vendor/tiny-pinyin.js`（17KB）：

- 它很聪明：**不带汉字→拼音词库**，而是借用运行环境自带的 ICU 中文排序（`Intl.Collator`）
  对 ~400 个「拼音边界汉字」二分查找，所以整个库只有十几 KB（还带姓氏多音字修正：曾→zeng、沈→shen）；
- **双击 index.html 就能跑**的前提不能破——所以不用 npm、不进构建流程；
- 迁到**微信小程序**时可以直接 `require('./vendor/tiny-pinyin.js')`，不需要"构建 npm"；
- MIT 许可原文随库一起放在 `js/vendor/tiny-pinyin.LICENSE`。

想升级/重新生成：

```bash
npm i --no-save tiny-pinyin
node tools/vendor-pinyin.js node_modules/tiny-pinyin   # 或 npm run vendor:pinyin
```

### 万一环境不支持拼音

极少数老环境没有 ICU 中文排序能力，此时 `Pinyin.mode` 会变成 `plain`，
搜索**自动降级为原文匹配**（中文/学号/电话照常能用），不会报错。
测试里专门覆盖了「浏览器 `<script>` 加载路径」和「降级模式」两种情形。

## 八、迁移到微信小程序

核心逻辑层已经按小程序的要求写好了（CommonJS + 无 DOM + 适配器模式），
`storage.js` 里甚至已经内置了 `createWxStorageAdapter(wx)`。

**最短路径**（详细步骤和可直接抄的代码见 [`docs/weapp-migration.md`](docs/weapp-migration.md)）：

1. 把 `js/core/` 整个目录复制进小程序项目；
2. 新建 `miniprogram/app.js`，换一个存储适配器：
   ```js
   const Storage = require('./core/storage.js');
   const Store = require('./core/store.js');
   const store = Store.create({ adapter: Storage.createWxStorageAdapter(wx) });
   ```
3. 5 个 tab 页对应 5 个 Page，`store.subscribe(() => this.setData(...))`；
4. UI 层（`js/ui/`）用 WXML/WXSS 重写 —— 这是唯一需要重写的部分。

## 九、常见问题

**Q：一批人打完了，怎么记？**
「记账」页搜班级（比如输「高一(3)」）→ 点「全选这 30 人」→ 填张数 → 保存。
一次提交，30 个学生各生成一条记录，钱按各自算，收谁的账都清楚。

**Q：选错人了 / 张数填错了怎么办？**
保存前：点已选标签上的 ✕ 移除、张数点「清零」重填。
保存后：点「撤销这一批」整批删除，或者去「记录」页删/改单条。

**Q：单价怎么改？改了以前的账会变吗？**
「设置 → 打印单价」改成新的即可（比如 0.25）。**不会变**：每条记录都冻结了当时的价格，
改价只影响之后的新记录。

**Q：数据存在哪？会丢吗？**
存在当前浏览器的 localStorage 里，不上传任何服务器（也就没有隐私问题）。
换设备、换浏览器、清理浏览器缓存都会丢失，所以：**重要数据请定期「设置 → 备份为 JSON」**。
（若提示「当前环境无法本地保存」，说明在隐私模式，数据仅当次有效。）

**Q：想换台手机继续用？**
旧设备「备份为 JSON」→ 传过去 → 新设备「从 JSON 恢复」。

**Q：一次收了 10 块，包含好几个学生的账怎么办？**
建议在「记录」页先按学生筛选再结算（每张收款单对应一个学生，账目清楚）；
跨学生合并结算会有二次确认。

**Q：能多人同时用吗？**
不能。这是单机版（localStorage）。需要多人/多设备共享，见迁移指南里的
「升级到云开发」一节——把存储适配器换成云数据库即可，业务逻辑不需要动。

## 十、离线使用（装到手机桌面）

这是一个 **PWA**：第一次联网打开后，Service Worker 会把所有资源缓存到本地，
**之后断网也能启动、记账、结算、导出**（数据本来就存在 localStorage 里）。

### 怎么装

| 设备 | 步骤 |
| --- | --- |
| **安卓（Chrome / Edge）** | 打开网页 → 底部会弹出「**装到桌面**」→ 点「安装」；也可以走菜单「安装应用 / 添加到主屏幕」 |
| **iPhone（Safari）** | 打开网页 → 底部提示「分享 → 添加到主屏幕」→ 点 Safari 的 **分享** 按钮 → 添加到主屏幕 |
| **电脑 Chrome** | 地址栏右侧的「安装」图标 |

装好从桌面图标进入是**全屏、无地址栏**的，和原生 App 没区别。

> **两个前提**
> 1. 必须是 `https://` **或** `localhost`。`file://` 双击打开时浏览器**禁止**注册 Service Worker，
>    `pwa.js` 会静默跳过（页面照常能用，但没有离线缓存，`localStorage` 也可能被禁用）。
> 2. 局域网 `http://192.168.x.x` 同理，不属于安全上下文，装不了。

### 部署到 GitHub Pages

`Settings → Pages → Source` 选 **Deploy from a branch**，分支 `main` + `/ (root)`，保存。
等一两分钟，手机打开就能装：

```
https://1821746019.github.io/recordSystem/
```

### 更新是怎么生效的

- **所有资源（包括 `index.html`）都走 stale-while-revalidate**：先用缓存**秒开**，
  同时后台用 `cache: 'no-cache'` 校验一次（Pages 会回 304，几乎不耗流量），
  真有新版就静默写回缓存 —— 所以**最多只陈旧一次启动**，用户无感知；
- `sw.js` 本身每次启动都会绕过 HTTP 缓存检查；发现新版本时**不会**打断你，
  而是在底部弹一条「发现新版本 · 刷新」，你点它才切换并重载；
- 想「立刻作废所有人的旧缓存」：把 `sw.js` 里的 `CACHE_VERSION` 改一下再发版；
- 缓存更新**不碰业务数据**：账本在 `localStorage`（`pps_data_v1`），和 Cache Storage 是两个仓库。

### 新增的文件

| 文件 | 作用 |
| --- | --- |
| `manifest.webmanifest` | 应用名、图标、`display: standalone`、主题色 |
| `sw.js` | 预缓存清单 + 缓存策略（导航缓存优先、资源 SWR） |
| `js/ui/pwa.js` | 注册 SW、安装提示、iOS 提示、新版本刷新提示 |
| `icons/*.png`、`icons/icon.svg` | 桌面图标 + favicon（192 / 512 / maskable / apple-touch） |
| `tools/render-emoji-icon.js` | 图标烘焙脚本（`npm run icons:emoji`，需一次浏览器渲染） |

### 图标为什么不直接用标题栏那个 emoji？

页面左上角是 `<span class="brand-icon">🖨️</span>`，那是一个**字符**，不是图片。它没法直接当图标用，原因有三：

1. `manifest.icons[].src` 只能指向图片文件（PNG/SVG），没有语法能表达「渲染这个字符」；
2. 同一个码点，安卓是 Noto Color Emoji、iOS 是 Apple Color Emoji、Windows 是 Segoe——
   **三套完全不同的画**，还随系统版本变；桌面图标必须是「定死的一张图」；
3. Apple Color Emoji 是专有字体（不可随项目分发），安卓的 Noto 是**位图**字体，放大到 512 会糊。

所以做法是：取 [Twemoji](https://github.com/jdecked/twemoji) 的**矢量稿**（同一个打印机图形、跨平台一致），
在浏览器里按 1024×1024 原生栅格化（矢量放大不糊）→ 按 alpha 包围盒等比缩放 → 合成到品牌蓝圆角底上，
最后输出 PNG，并把同样的路径内联成矢量 `icon.svg` 当 favicon。图形许可 CC-BY 4.0，见 `icons/twemoji.LICENSE`。

想改回纯几何图形：`npm run icons:fallback`。

> ⚠️ 新增或删除源文件时，**记得同步 `sw.js` 里的 `SHELL` 数组**，否则离线会缺文件。
> `tests/pwa.test.js` 会拿 `index.html` 里的引用逐条比对，漏了直接测试失败。

### 数据安全（这条比离线更重要）

PWA 只解决「断网也能打开」，**不解决「数据不会丢」**：

- iOS 对「没装到桌面」的网站在 7 天不访问后会清理存储；装到桌面后不受这个限制；
- 安卓清理浏览器数据、卸载浏览器、换手机，localStorage 一样会没；
- 所以：**正式用之前先「备份为 JSON」一次练手，之后建议每周备份一次**（存网盘/发给自己都行）。
  恢复时用「设置 → 从 JSON 恢复」，支持「覆盖」和「合并」两种模式。

## 十一、开发提示（踩过的坑）

1. **凡是依赖"当前选择/当前输入"的文案，都要在 `updateCalc()` 里手动同步**。
   勾选学生、点 `+ / −`、点快捷数字都只改 state、**不触发整页重绘**，
   所以这些地方必须自己更新 DOM，否则会显示陈旧的值：
   - 张数 `<input>`（曾出现「金额变了、输入框还显示 0」）
   - 保存按钮上的人数（曾出现「一直显示上次保存时的人数」）
   - 「已选 N 人」徽标、金额区、`#q-counts`
   `tests/ui-smoke.test.js` 里对这三类都各有一条回归用例锁死。
2. **页面事件必须挂在「每次重绘都新建」的容器上** —— 见 `js/ui/app.js` 的 `mountView()`。
   `#view` 是常驻元素，若把点击事件直接委托到它上面，每重绘一次就多叠一层，
   导致**点一次「编辑」弹出 N 个弹窗**。现在每次 `render()` 都新建 `.view-root` 作为挂载点。
3. 挂到 `document` / `window` 上的监听（如「点击空白处收下拉」），必须在 `P.UI.cleanup` 里解绑。
4. 重绘后要用**当前** DOM 重新取元素（`DOM.qs('#id')` 从 document 取），
   不要拿重绘前的旧容器去找——那样会拿到已废弃的节点，导致输入框掉焦点。
5. 金额一律用「分」的整数，只在展示时用 `U.money()` 格式化；改算法就去 `pricing.js` 并补测试。
6. 数据变了不用手动改 DOM，调 `app.refresh()` 即可（`store.subscribe` 也会自动重绘当前页）。
7. **搜索不要用"全拼里 indexOf 子串"**：`wa**ng-y**uxin` 里能搜出 `gy` 这种跨音节的假命中。
   现在的规则是「关键字必须从某个字的拼音开头开始」（见 `core/pinyin.js` 的 `startsAtSyllable`）。
8. **用了 `el.hidden = true` 的元素，不要在 CSS 里给它写 `display`**。
   浏览器默认样式 `[hidden] { display:none }` 会被作者样式（比如 `.combo-list { display:flex }`）**盖掉**，
   于是元素藏不起来（曾导致「点空白处下拉列表不消失」）。
   样式表顶部有一条 `[hidden] { display: none !important; }` 兜底，
   `tests/ui-smoke.test.js` 里也有静态断言守着这条规则别被删掉。
9. **逗号批量勾选是「状态机」，不是简单的过滤**（见 `js/ui/quick.js` 的 `autoSelectByTokens`）：
   - `state.quick.autoMap` 记录「每个词当前勾了谁」，词删掉/改短时按它把人退掉；
   - `state.quick.excluded` 记录「用户手动取消过谁」，自动勾选永远跳过这些人；
   - 搜索框清空 = 这一轮结束，两个字段一起重置。
   改这段逻辑时，务必保住「手动取消不会被自动勾选覆盖」这条（有专门的回归用例）。
10. **张数可能是 0.5 的倍数**：任何累加/统计都**不能用 `parseInt`/`Utils.toInt`**，
   要用 `Number(x)` 或 `Pricing.toSheets()`；展示统一走 `U.qty()`（15 → "15"，15.5 → "15.5"）。
   金额相加仍用「分」整数，`Pricing.calculate` 里已带 `Math.round`。
11. **PWA 有三个坑**（都在 `tests/pwa.test.js` 里锁着）：
    - 新增源文件必须同步 `sw.js` 的 `SHELL`，否则**离线时会缺文件**（联网时完全看不出问题）；
    - **不要在 `install` 里 `skipWaiting()`**：用户正记着账、资源被换掉会白屏；
      正确做法是 `pwa.js` 弹「新版本 · 刷新」，用户点了才切换；
    - `file://` 和局域网 `http://` 不是安全上下文，SW **不会**注册（也不该尝试），
      `pwa.js` 里用 `isSecure()` 提前跳过，别把这个判断删了。
